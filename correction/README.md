## 1. 词库来源

**原始词库（只读，未做任何修改）**由 `--source <目录>` 指定；未指定时使用：
`%USERPROFILE%\Documents\AI Live Clipper\词语库\`

| 文件 | 分类 | 大小 | 状态 |
|---|---|---|---|
| 热词库.txt | hotword | 10.6 KB | 120 行 |
| 人物库.txt | person | 52.4 KB | 846 行 |
| 影视作品名.txt | movie | 12.1 KB | 251 行 |
| 书本.txt | book | **0 字节** | 原始文件本身为空 |

原始文件的**快照副本**放在 `dictionary/raw/`（转换只读它，桌面上那份永远不动）。

### 原始格式（三种，各不相同）

```
热词库.txt        序号/标准词/变体1、变体2、变体3
                  → 341/那咋了/那咋拉、那咋啦、纳咋了、哪咋了

人物库.txt        序号/标准名/(变体1 变体2 变体3)           ← 空格分隔
                  → 1/疯狂小杨哥/(小羊哥 小杨哥 小杨哥儿 疯狂小杨)
                  序号/标准名/(谐音：A、B；外号：C)          ← 标签分隔
                  → 517/李白/(谐音：理白、里白；外号：诗仙；叫错：李百、李柏)

影视作品名.txt    序号/标准名/(打错字：X；叫错：Y→Z；外号：W) ← 说明文字最多
                  → 1/月鳞奇迹/(打错字：鳞→麟，纪→记；谐音外号：月0奇迹)
                  → 17/妖猫传/(叫错：猫妖传)
                  → 76/机智的医生生活/(常被简称/叫错)          ← 纯说明，无别名
```

**难点**：影视库的括号里混着大量**给人看的注释**，不是可替换的错误词。
转换器做了三层过滤（详见 §3）。

## 2. 转换后的格式（程序使用版）

四个文件，均由 `converter.py` 生成（**原始文件不覆盖**）：

```
dictionary/converted_hot_words.json
dictionary/converted_people.json
dictionary/converted_books.json       ← 空条目列表（原始书本库为空，结构保持一致）
dictionary/converted_movies.json
```

每个文件：`{"meta": {...}, "entries": [...]}`，条目结构：

```json
{
  "canonical": "妖猫传",
  "aliases": ["猫妖传"],
  "category": "movie",
  "priority": 2,
  "context_tags": ["movie", "typo"],
  "description": "叫错：猫妖传",
  "source": "影视作品名.txt:17",
  "updated_at": "2026-09-13",
  "is_pattern": false
}
```

| 字段 | 含义 |
|---|---|
| `canonical` | 标准词（替换的**目标**） |
| `aliases` | 可能的错误写法（替换的**来源**），已去重、已过滤注释 |
| `category` | `hotword` / `person` / `book` / `movie` |
| `priority` | 0-3。分类基础分（人/书/影=2，热词=1）+ 别名≥3 个再 +1 |
| `context_tags` | 领域标签：`homophone` / `nickname` / `typo` + `game` / `livestream` / `film` / `book` / `anime` |
| `description` | 原始括号内的说明，给人看 |
| `source` | 溯源用：`文件名:行号` |
| `is_pattern` | 标准词含 `××`/`XX` 占位符（如「拼好×」）→ **不做字面匹配** |

**转换结果**：

| 分类 | 条目 | 别名 | 合并重复行 |
|---|---|---|---|
| hotword | 92 | 393 | 28 |
| person | 696 | 2298 | 147（原库分两段落号，同一人名重复出现） |
| book | 0 | 0 | 0 |
| movie | 250 | 196 | 0 |
| **合计** | **1038** | **2887** | |

重新生成：`python converter.py`（或 `python converter.py --sync-raw` 先从桌面同步原始库）。

## 3. 转换时踩到的三个坑（已固化在 converter.py）

1. **`X→Y` 是字级纠错，不是整词别名**
   `鳞→麟` + 标准词 `月鳞奇迹` → 生成别名 `月麟奇迹`。
   `魏劭→魏助/魏刀/魏勋`（标准词 `折腰`）：箭头两端都不在标准词里 → **只当说明**。
   若不铺开箭头，`魏刀`/`魏勋` 会被当成 `折腰` 的别名 → 灾难性误替换。

2. **关联实体外号不是错字**
   `权力的游戏` 的外号 `二丫` / `龙妈` 跟标准词**一个字都不重合**。
   ASR 错字几乎总保留部分原字，所以规则是：**中文别名与标准词零重合 → 丢弃**。
   （`摩天轮`↔`摩天大楼` 重合 2 字 → 保留；`巨石强森`↔`摩天大楼` 零重合 → 丢弃）

3. **说明文字必须过滤**
   含 `易读错 / 常读成 / 难读 / 简称 / 被叫 / 剧名` 等标记的片段一律不收；
   但先剥前缀再判断——`常被叫白蛇传` → `白蛇传` 是可以收的。

## 4. 纠错逻辑（不是暴力替换）

```
ASR 原文
  ↓ 候选检测（只匹配 aliases，最长优先）
  ↓ 上下文判断（句子 + 全文领域画像）
  ↓ 置信度评分（四维加权 × 歧义系数）
  ↓ 三选一决策
      ├─ replace      替换
      ├─ keep_suggest 保留原文 + 提示候选
      └─ keep         保留原文
```

### 评分公式（`scorer.py`）

```
score = (0.15 × 分类先验
       + 0.25 × 字形字音相似度
       + 0.40 × 上下文匹配
       + 0.20 × 替换后通顺度) × 歧义系数
```

| 维度 | 说明 |
|---|---|
| **上下文 0.40（权重最高）** | 决定对错的不是词本身而是语境。分类强语境（电影院/主播/小说）+0.6 起；条目领域标签（game 等）+0.6；**文档级一致性** +0.6；全文领域倾向最多再 +0.35。各路证据取 `max` 叠加，不会互相覆盖 |
| **相似度 0.25** | 编辑距离 0.5 + 字符集合重合 0.3 + 长度比 0.2。同音替换通常只差 1-2 字 |
| **通顺度 0.20** | 基准 0.55；紧邻动作动词 +0.15；处于分句边界 +0.15；后接通用抽象搭配（`的等待`/`的爱情`）-0.35；前面是程度副词（`很`/`挺`）-0.20 |
| **分类先验 0.15** | movie 0.62 / book 0.60 / person 0.55 / hotword 0.45（热词多义性最强） |
| **歧义系数** | 一个写法对应多个标准词 ×0.65；该写法本身也是别人家标准词 ×0.70；候选≤2 字 ×0.90 |

### 阈值

| 区间 | 决策 |
|---|---|
| `score ≥ 0.62` | **replace** |
| `0.40 ≤ score < 0.62` | **keep_suggest**（保留原文，输出候选） |
| `score < 0.40` | **keep**（保留原文） |

### 四条安全闸门（在评分之外，硬约束）

1. 只匹配 `aliases`，**不匹配标准词**——原文已经是对的就不动。
2. **标准词保护区**：候选若落在原文某个标准词内部（如「陈翔六点半」里的「陈翔六点」），直接跳过，不会把正确的长词咬掉一半。
3. **模板条目跳过**：`is_pattern=true`（含 `××`）不参与字面匹配。
4. **时间戳保护**：`[00:12:34]` 内容永不参与匹配与替换。

### 实测行为

| 输入 | 输出 | 决策 |
|---|---|---|
| 今天玩**永久无间** | 今天玩**永劫无间** | replace 0.76（游戏语境命中） |
| **永久无间**的等待 | 不变 | keep 0.35（通用搭配，非游戏名） |
| 昨天去**电影院**看了**猫妖传**，特效真不错 | …看了**妖猫传**… | replace 0.83 |
| 昨天**看**了猫妖传 真的不错 | 不变 + 提示候选 | keep_suggest 0.59（只有弱线索） |
| 周末带孩子去坐**摩天轮** | 不变 | keep 0.36（本义是游乐设施） |
| 我昨天买了**三斤**苹果 | 不变 | 无候选（本身是标准词） |
| 这个**主播**叫**小杨哥**，**粉丝**很多 | …叫**疯狂小杨哥**… | replace 0.80 |
| **王博主**测评了一下这款手机 | 不变 | keep 0.39（「博主」是候选自己的字拼出来的，不作证据） |
| 直播间里**风哥**讲得真好。风哥还说了别的。 | 两处都→**峰哥** | replace 0.68 / 0.63（第二处靠文档级一致性） |

⚠️ 前两行的「永劫无间」是**演示词条**（`corrector._demo_entry()`），
只为演示游戏语境规则，**未写入任何词库文件**。

## 4b. 两条上下文防线（2026-09-13 修复）

### 防线一：候选不能给自己作证

**问题**：`王博主测评` → `王勃主测评`。原文是「王博主 测评」（博主王博），
跟唐代诗人王勃毫无关系。根因：候选「王博」右侧的「主测评」拼出了「博主」，
而「博主」正是人物类的强语境词 —— **候选词用自己的字造出了支持自己的证据**，
context 被打到 0.95，置信度 0.67 越过替换线。

**修法**：扫上下文关键词时，命中区间与**候选词区间重合**的一律剔除
（`scorer._keyword_hits(sentence, keywords, span)`）。
候选自己的字、以及横跨候选边界的词，都不算语境证据。

**效果**：0.67（replace）→ **0.39（keep）**。

### 防线二：文档级一致性（含安全阀）

**问题**：同一场直播里，ASR 把同一个人名写成两种（峰哥 3 次 / 风哥 12 次）。
逐句独立打分只看得见单句，结果**改一半留一半** —— 那比不改更糟。

**修法**（`corrector._apply_consistency`）：对同一个 `(别名, 标准词)` 组合，
满足其一即认定一致：

- **标准词见证**：标准词在本篇其他位置**原样出现过**（时间戳保护区内的不算）
  —— 这是文稿能给出的最强证据，等于稿子自己把答案写出来了；
- **锚点背书**：该组合里已有一处被高置信度判定为听错。

成立时，灰区候选重打分并计入 `consistent=True`（等价于一次强语境命中）。

**安全阀（关键，不能省）**：只对**已进入灰区**（`score ≥ 0.40`）的候选生效。
文档级证据只能把「差一点就过线」的推过去，**绝不能凭空造出一个判断** ——
否则一处误判会顺着一致性扩散到全文，那比漏改危险得多。
多义别名（同一写法对应多个标准词）同样不做外推。

**效果**（临时词条 `峰哥=风哥`，测试视频.txt）：

| | 修复前 | 修复后 |
|---|---|---|
| 替换 | 4 / 14 | **12 / 12** |
| 遗留「风哥」 | 8 | **0** |
| 无关候选被误提升 | — | 0（`无用→吴用`、`吃瓜→吃瓜本呱` 仍在灰区） |

### 一个必须说清的边界

一致性**没有**让误判变多。实测 `王勃的诗写得很有气势。王博主测评了一下这款手机`：
`王博` 单句证据不足（0.39 < 0.40），即使「王勃」在文中原样出现过（witness 成立），
安全阀也把它挡在了灰区之下，**不替换**。

但如果句子里**另有**真实的「博主」命中（如「…博主讲得很实在」），
`王博主测评` 仍会被替换 —— 这是**既有的**歧义（0.67），
开不开一致性结果完全相同。真实区分「唐代诗人王勃」和「博主王博」需要世界知识，
当前不做（见 §8）。

## 6. 用法

```python
from correction import AsrCorrector

c = AsrCorrector.from_dictionary_dir()        # 默认读 correction/dictionary/
result = c.correct("昨天去电影院看了猫妖传")

result.text            # 已替换文本
result.applied         # 实际替换（含分数、理由、位置）
result.suggestions     # 灰区候选（保留原文，交给人工/上层）
result.decisions       # 全部决策（含被否决的），可审计
result.to_dict()       # 全量 JSON

# 文字稿行：时间戳不动，只改台词
line, r = c.correct_transcript_line("[00:12:34] 这个主播叫小杨哥")
```

命令行：

```bash
python converter.py                      # 重新生成 converted_*.json
python converter.py --sync-raw           # 先从桌面同步原始库再转换
python corrector.py --stats              # 词库统计
python corrector.py --with-demo --text "今天玩永久无间"
python correction/test_minimal.py        # 24 项测试
```

## 6b. 接入测试流程（2026-09-13）

新增三个文件，**不改 pipeline.py 一个字**，只在其后插入一个独立步骤：

```
ASR 输出  transcripts/<name>.txt              ← 原样保留
   ↓ 【新增】correction/pipeline_step.run_correction_step()
transcripts/corrected/<name>.corrected.txt             ← DeepSeek 默认读这个
transcripts/corrected/<name>.correction_report.json    ← 原文本/修正文本/修改位置/置信度
   ↓
DeepSeek 高光分析（analysis.analyze_transcript_v2，未改动）
   ↓
transcripts/corrected/<name>*.comparison.json          ← 纠错前后高光对比
```

| 文件 | 职责 |
|---|---|
| `pipeline_step.py` | **新增步骤**：ASR 稿 → corrected 稿 + 审计 JSON（原文本 / 修正文本 / 修改位置 / 置信度四维拆解 / 理由） |
| `run_pipeline_test.py` | 完整跑测：复用或重跑 ASR → 纠错 → DeepSeek 分析 corrected 稿，并跑一遍原稿做对照 |
| `test_pipeline_step.py` | 15 项离线接入测试（分析函数用假函数注入，不烧 API） |

运行：

```bash
python correction/run_pipeline_test.py --transcript 测试视频.txt --no-api    # 离线接线验证
python correction/run_pipeline_test.py --transcript 测试视频.txt --mode 快速  # 完整流程 + 前后对比
python correction/run_pipeline_test.py --transcript 测试视频.txt --extra-entry "峰哥=风哥"  # 临时词条（不落盘）
python correction/test_pipeline_step.py                                      # 15 项离线测试
```

**红线**：不修改 ASR、不修改 DeepSeek 提示词/分析逻辑、不修改 UI、不修改 pipeline.py；
原始 transcript 只读（测试里有字节级断言）。

### 实测（三份真实稿，离线）

| 稿子 | 规模 | 替换 | 灰区候选 | 说明 |
|---|---|---|---|---|
| 测试视频.txt | 41 行 / 2.5k 字 | 0 | 2 | 简体，内容不含词库实体 |
| 测试视频2.txt | 2268 行 / 50k 字 | 0 | 1 | 修复前那处 `王博→王勃` 误判**已消除**（见 §4b） |
| 测试视频4.txt | 888 行 / 21k 字 | 0 | 2 | **繁体稿**，简体词库完全匹配不上 |

### 本轮暴露的三个真问题

1. ~~**误判：`王博主测评` → `王勃主测评`**~~ ✅ **已修**（见 §4b 防线一）
   根因：人物强语境词「博主」正好紧贴在候选词右侧（`王博` + `博主`），
   被当成上下文证据（context 0.95）→ 置信度 0.67 越过替换线。
   实际「王博主」= 博主王博，跟唐代诗人王勃毫无关系。
   修法：扫上下文关键词时排除与候选区间重合的命中。现为 **keep 0.39**。

2. **词库覆盖率 ≈ 0**：词库是「网红 / 热词 / 影视作品」，测试视频是「商品测评」，
   三份稿合计只命中 0～1 个标准词。覆盖率问题不是纠错算法能解决的。

3. **繁体稿完全失效**：测试视频4 是繁体输出，简体词库零命中。
   要么 ASR 阶段统一简体，要么词库做简繁双写。

### 顺带发现：真实 ASR 的不一致

测试视频.txt 里同一个人被 ASR 写成两种：

| 标准写法 | ASR 错写 | 出现次数 |
|---|---|---|
| 峰哥 | 风哥 | 3 / **12** |
| 徐英宇 | 徐英语 | 5 / **1** |

这类「主播自己的名字被写错」才是本项目最该修的错误，而现有词库**没有这些名字**。
用临时词条（`--extra-entry "峰哥=风哥"`）验证：修复前 12 处风哥只修回 4 处，
其余落进灰区——因为打分是**逐句独立**的，只有那句里出现「观众」等强语境词才够分。

✅ **已修**：加了**文档级一致性规则**（见 §4b 防线二）——标准词见证或锚点背书成立时，
灰区候选沿用同一判定，并带「只提升灰区、不得凭空造判断」的安全阀。
修复后 **12/12 全部统一为「峰哥」**，全文不再两种写法混用。

## 7. 独立性与性能

- **纯标准库**（`json / re / dataclasses / pathlib / unittest`），零第三方依赖，可离线跑。
- 测试里有一条硬断言：`correction` 导入后 `pipeline / analysis / asr / ui / desktop / config`
  都不得出现在 `sys.modules` —— 从机制上保证没被主流程拖进来。
- 性能：63,000 字 / 1500 行带时间戳文字稿 ≈ **0.29s**（保护区用掩码实现，
  早期版本写成 O(字符数×时间戳数) 是 4.5s，已修）。

## 8. 已知限制（故意不做）
