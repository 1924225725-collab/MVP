## 二、每个修改的原因

### 任务 1：真实处理进度

**问题**：识别一场 51 分钟直播要十几分钟，界面上只有一个转圈的进度条和一句"语音识别"。
用户无法判断程序在跑还是卡死 —— 这是"以为软件死了"的直接来源。

**做法**：
1. 建立六个阶段：读取视频 → 提取音频 → VAD 人声检测 → 语音识别 → AI 分析 → 生成结果。
2. **语音识别用真实百分比**：faster-whisper 每吐出一句话都带着这句话在音频里的结束时间，
   拿它当分子、视频总时长当分母 → `45%　23:10 / 51:00　已识别 312 句`。
   进度条和实际处理到第几秒完全对得上，不是定时器刷出来的假动画。
3. **算不出进度的阶段如实说"进行中"**：VAD 检测要扫完整段音频才知道谁在说话，
   没法给百分比 —— 就给不确定进度条，绝不编一个数字。
4. **AI 分析阶段**：解析分析过程自己的日志（`[海选] 区块 3/12`、`[复审] 批次 2/3`），
   海选和复审有真实批次 → 真百分比；其余是里程碑 + 明确写出"正在做什么"。
   全程**不改 analysis/ 一行代码**。
5. 进度上报带节流（同阶段内 0.15 秒 / 0.5% 以内的事件丢掉），否则每秒几十条会淹掉界面。

### 任务 2：首次安装 / 首次启动不卡死

**定位到的原因（"偶尔卡死"具体是什么）**：

| 位置 | 原因 | 后果 |
|---|---|---|
| 安装器解压 | 12 万个文件、126 MB 在**主线程**里解压，主线程只调 `update_idletasks()` | 界面十几秒不刷新 → Windows 标记「未响应」 |
| 安装器统计目录 | `_dir_size_kb()` 在主线程递归遍历刚装好的上万个文件 | 又卡几秒 |
| 安装器建快捷方式 | `subprocess` 调 PowerShell，主线程同步等待 1~3 秒 | 再卡一下 |
| 首次启动 | 模型检测在主线程扫 HuggingFace 缓存、项目列表在主线程读全部 `project.json` | 启动白屏 |

**做法**：
- 安装器：**所有重活搬到后台线程**，主线程每 60 毫秒看一次进度队列刷新界面。
- 启动：界面**先显示出来**，环境自检放后台；项目列表改异步加载（并处理了"异步结果覆盖新数据"的竞态）。
- 增加**安装日志**（`%TEMP%\AILiveClipper_setup.log`，装完复制一份到安装目录）和
  **启动日志**（`工作区/logs/desktop_startup.log`，记录每个阶段的耗时）。
  实测启动到窗口显示 **0.15~0.24 秒**。

### 任务 3：环境自检系统

**问题**：出错时统一显示「视频处理失败」，用户不知道该换视频还是重装程序。

**做法**：新增 6 项自检 + **四类问题归类**：

| 检查项 | 类别 | 出问题时说什么 |
|---|---|---|
| FFmpeg 组件 | 程序组件 | "程序自带的音视频组件不完整，请重新安装" |
| 语音识别依赖 | 程序组件 | "程序组件不完整，请重新安装" |
| **人声检测模型（VAD）** | 程序组件 | 同上（**V0.5.1 就是这里漏文件**，所以单独查它） |
| 本地模型 | 模型 | "点模型管理 → 一键安装" / "做完整性校验" |
| 配置文件 | 配置 | 清单坏了 / 没填钥匙（本地识别不受影响） |
| 数据目录权限 | 权限 | "写不进去，换位置或联系管理员" |

- 启动后**在后台**自动跑一次，有问题才弹窗；没问题不打扰。
- 结果完整展示在「🔧 开发者视图 → 环境自检」，随时可"重新自检"。
- 报错弹窗现在也带类别前缀（【视频问题】/【程序组件问题】/【模型问题】/【权限问题】）。

### 任务 4：修复卸载程序

**定位到的三个真因**（都对上了用户报的现象）：

1. **卸载器自己就在安装目录里** → Windows 不允许删除正在运行的程序文件 →
   "删掉安装目录"这一步**必然失败**；而旧版只尝试一次，失败就永久残留。
2. **PyInstaller 单文件程序的引导进程**会一直占着 `install\uninstall.exe`，
   实测退出能拖到 **40 秒以上**；临时副本等不了那么久 → 每次卸载都"差一个文件"。
3. **删除失败被静默吞掉**，没有任何日志；注册表删除失败也无人处理 →
   「应用和功能」里一直留着。

**做法**：
1. 卸载器**先把自己复制到 %TEMP% 再执行**，自己不在被删目录里。
2. 删除带重试；实在删不掉的，**交给系统在后台继续删**（PowerShell 循环，最多 120 秒）。
   这里踩了个坑：用 `DETACHED_PROCESS` 启动 `cmd.exe` 时命令**根本不会执行**
   （cmd 需要控制台），所以后台清理静默失效 —— 改成 PowerShell 脚本后 1 秒内删净。
3. **注册表必定清理**，保证「应用和功能」里不再残留（这是任务要求的硬指标）。
4. 全流程写日志（`%TEMP%\AILiveClipper_uninstall.log`）。
5. "程序还在运行"从**中止卸载**改为**警告但继续清理** ——
   旧行为会导致"点了卸载什么都没发生"，正是用户报的 bug 之一。

### 任务 5：安装卸载自动化验收

新增 `packaging/test_install_uninstall.py`（35 项），在临时目录里跑完整生命周期：
静默安装 → 检查安装结果 → 首次启动 → 真跑一次本地识别 → 静默卸载 → 检查残留 → 重装并测试"连数据一起删"。
每次运行结束都有**兜底清理**，保证不给测试机留垃圾。

## 五、剩余风险

| 风险 | 说明 | 建议 |
|---|---|---|
| **未在真正的干净机器上安装过** | 所有测试都在本机（有 HuggingFace 缓存、有 .venv）跑的；虽然是独立工作区和独立安装目录，但仍不是"全新 Windows" | 找一台没装过环境的机器实测一次 |
| **首次运行无模型时的"一键安装模型"未联网验证** | 本机模型已在缓存里，走的是"沿用缓存"分支；真下载流程（进度/断点续传）没实测 | 断网/干净机验证 |
| **AI 分析未端到端验证** | 真实 API 分析要花钱，按约定未跑 | 用户明确要求时再跑一次 |
| 卸载仍依赖 PowerShell | 系统策略禁止 PowerShell 的机器上，快捷方式与后台清理会失效（会记日志，不影响注册表清理） | 已降级为"尽力而为"，注册表清理走纯 winreg 不依赖它 |
| 安装包体积 138 MB | 含 ffmpeg（87 MB）+ Qt + 推理引擎；模型另算 | 可考虑 ffmpeg 换成精简版，但会牺牲兼容性 |
| 卸载器退出仍偏慢 | PyInstaller 单文件程序的引导进程释放 exe 句柄要几十秒；已用后台清理兜住 | 若想根治，可把卸载器改为 onedir 模式 |
