# v0.4 Step 3 产品级审计与方案 ——「什么叫值得剪」的重定义

日期：2026-09-09
作者：Agent（晨曦）
性质：**纯分析，未改任何代码**。基于对 Step 1/2/3 实际代码 + prompt 的逐行审计，以及这次 51 分钟真实测试（精细模式）的人工对照。

> 结论先行：这不是"评分不准"或"阈值不对"的问题。是**高光单位定义错了**——系统从头到尾在找"有趣的一句话"，而你要找的是"完整的娱乐事件"。修这个，比调任何分数都重要。

---

## 1. 当前 Step 3 的核心问题（按严重程度排序）

### 根因 #1（最严重）：高光单位错了 —— 海选产的是"爆点句"，不是"事件种子"
`_SCREENING_TEMPLATE`（Step1.5 海选）让 AI「宁多勿少」「每段至少挑 1 个最有潜力的候选」「看开头 3 秒会不会停」，却**从不告诉 AI 一个候选应该是一个多长的完整事件**。结果 AI 在 180s 热区里只挑"最炸那句"报成一个 20-30s 短候选。真实测试 36 个候选 → 事件中位时长仅 24 秒。**病根比聚合更早，在海选。**

### 根因 #2：聚合层把碎片拆得更散，且拆开的碎片"失忆"
`_run_event_aggregation` 对 AI 判 `split` 的簇，用 `_make_event(split=True)` 拆成单候选事件，并把 **summary/structure 置空**。复审面对的是光秃秃时间戳+原文，没有故事锚点 → 只能按孤句判断 → 看不出完整故事就低分。真实测试：27 事件里 23 个单候选、12 个被 split、微波炉事件被拆成 5 个 D。

### 根因 #3：评分模型奖励"俏皮句"，不奖励"值得剪的事件"
权重 `hook30/contrast25/persona20/standalone15/completeness10`：hook+contrast+persona = 75% 全压在"这句话好不好玩"，completeness（故事完整度）只占 10。加上复审打分锚偏袒短俏皮句，导致：完整罐头事件 71 分 B，一句"像墙皮"俏皮话 84 分 A。**评分在结构性奖励短爆句。**

### 根因 #4："AI 没理解"被当成"内容没价值"
`NEGATIVE_RULES` 里有"依赖上下文"这条；复审对 split 碎片无结构可判；四类失败（真没价值/上下文不够/事件不完整/AI 不确定）全压成一个 D。AI 的困惑被包装成事件的缺陷。微波炉事件即铁证。

### 根因 #5：单分制无法表达"爆款价值 ≠ 素材保留价值"
生病网友那个案例，用户判"不是爆款但值得留素材"，系统只能塞进一个"娱乐传播分"→ 77.5 的 B，两头不靠。

### 根因 #6（次重）：recommended 引导"剪到 payoff 就收"
复审模板推荐段写死"在哪完成 payoff / payoff 一完就收 / 别拖无关内容" → 即便事件完整，AI 也只剪 payoff 一小段（真实：罐头 196s 事件 rec 砍到 150s，ev-008 167s 事件砍到 44s）。

> 说明：**batch 评分漂移、global ranking 未统一、report 影响推荐 —— 这三个经代码审计确认不存在问题**（各 batch 同用一套 `_weighted_final`/`config`；排序按统一 final_score；report 只生成文本不进 `_select_quantity`）。

## 2. 为什么会出现十几秒短片

不是某一处，是**四层叠加**，每一层都在往短推：

| 层 | 代码/prompt 位置 | 怎么把事件推短 |
|---|---|---|
| ① 海选候选粒度 | `_SCREENING_TEMPLATE`：宁多勿少 + 每段挑最有潜力 + 开头3秒钩子 | 180s 热区里 AI 只报"最炸一句"成 20-30s 候选，完整事件被切成多段漏报 |
| ② 聚合拆分 | `_run_event_aggregation` 的 split 分支 + `_dedupe_events` 边界 `>`bug | 长事件被 AI 判 split 拆成短碎片；重叠碎片（微波炉）因 `topic>0.5` 严格大于而漏合并 |
| ③ 复审推荐措辞 | `_REVIEW_TEMPLATE` 推荐段："payoff 一完就收""别拖无关内容" | 即便事件完整，AI 也只保留 payoff 前后，主动砍掉 setup/中间铺垫 |
| ④ 事件本身短 | 前面 ①② 的产物 | recommended 只是忠实地反映"它拿到的就 24 秒" |

**关键认识**：recommended_duration 本身没有硬性压短（有 drift 兜底保护长事件不超界），但它**忠实地继承了上游的短**。真正的短源是 ①②。所以不能靠"把 duration 下限设成 30s"这种表面修复——那只会让 AI 把一个 8 秒就完整的东西硬拖到 30 秒，违背你"短事件仍可 8-15s"的要求。

## 3. 为什么 S 会高估

**不是阈值问题，是评分奖励错对象**：

1. **五维是"爆点强度评分"，不是"娱乐事件传播价值评分"**。hook（开头钩子）+ contrast（反差）+ persona（主播表现）= 75% 权重，这三维奖励的是"这个瞬间多有梗/多会表演"。而你要判断的是"这段作为独立视频，值不值得剪/发出去有没有人看"——后者更依赖**它是不是一个能独立成立、有来龙去脉、能留住人的完整故事**，这部分权重只有 completeness 10 + standalone 15 = 25%。

2. **重复计分存在**：contrast（反差意外）和 hook（三秒吸引力）高度相关——一个强反差本身就是最好的 hook；persona（主播表现力）也常是 contrast 的表现载体。同一个"黄腐鸡当咖啡"式瞬间，会同时在 hook 和 contrast 各拿一次高分。三个维度挤在一起重复奖励同一个"有梗瞬间"，进一步把普通内容推高。

3. **"事件完整"成了隐形的"不完整就吃亏"，但没有正向激励**：AI 对 split 碎片没法评 completeness（没结构可看），只能给低分；但对"一句俏皮话"却给 completeness 7——因为俏皮话自带"起→承→落"的瞬间完整性。于是**短俏皮话反而在完整度上不吃亏**，加上 hook/persona 高，轻松上 S/A。

4. **缺"反证/否决"**：现在没有任何"即便局部维度很高，但传播价值明显不足就不能进顶"的机制。S/A 纯粹由加权分够不够决定。**S 本应是稀缺的（全场 1-2 个），现在却可以有一批 84 分。**

---

## 4. 为什么 B/C 混杂

B/C 是"非 A 且非 D"的**兜底桶**，系统没有在这个区间做任何区分。挤进 B/C 的是三类本质不同的对象：
- **真正的完整娱乐事件被压分**（罐头 71、生病网友 77——其实是 A/B 级或"素材级"）
- **平庸短句恰好卡在及格线**（凑到 60-79 的普通内容）
- **有内容价值但非爆款的素材**（用户点👍的生病网友——不该按"娱乐分"排进 B 和真爆梗混一起）

根源是**单维分数**。你没法用一个"娱乐传播分"同时表达"这是爆款""这是好素材""这是普通"。B/C 混杂 = 分数语义过载。

## 5. 为什么 D 会误杀

**直接原因**（代码确认）：
- `_make_event(split=True)` 把 summary/structure 置空 → 复审没有故事锚点
- 复审对无结构碎片只能从孤句推，五维给低分（微波炉 dims 3/2/4/2/3 → 28 分 D）
- `NEGATIVE_RULES` 的"依赖上下文"让 AI 把"我没看到完整背景"标成内容缺陷
- reject_reason 是 AI 现编的套话（"画面散乱""无故事情节"），**把 AI 的理解困难伪装成事件的客观缺陷**

**本质**：系统用"AI 能否在一个孤句上自圆其说地打出高分"来代理"这个事件值不值得剪"。AI 对碎片困惑 → 打不出分 → D。**"不确定"与"没价值"被混为一谈。**用户要区分的五类（truly_low_value / context_insufficient / event_incomplete / ai_uncertain / worth_clipping）现在被压成两级（≥50 推荐 / <50 D），中间没有重审、降置信、留候选的路径。

## 6. 当前 Event Model 是否正确

**部分正确，但缺了关键一环**。

现有：`Transcript → Event Cluster(本地粗聚类) → Event Judge(AI判同一簇+边界) → Review`

**做对了**：Event Judge 确实在判"几个候选是不是一件事"并给事件边界/structure（setup/dev/payoff）。罐头事件能聚合就是证明。

**缺了三件事**：
1. **海选没按事件供给候选**——Event Judge 是在"拼 AI 之前切碎的句子"，巧妇难为无米之炊。应该让海选阶段就知道"我在找一段能独立成立的事件，可以 10s 也可以 3 分钟"，而不是"找最有梗的瞬间"。
2. **split 后的事件"失忆"**——被判拆开的事件没有 summary/structure 兜底，复审无锚点。
3. **Event Judge 只做"同一簇内判断"**，不做"这个事件完整吗？它作为独立短视频成立吗？"——它把"判断边界"和"判断价值"劈成了两半，中间那段"这个事件从 setup 到 payoff 是不是完整一段"没人负责。补全应在 judge 与 review 之间加一个"事件完整性 + 价值类"判断（见方案）。

**所以 Event Model 的方向对，但链路断了三环**。

## 7. 是否需要重新定义评分模型

需要。但**不是推翻五维**，而是做两件事：

### (A) 把"爆点强度五维"重命名为"它是不是一个值得剪的完整娱乐事件"
现在的五维本质测的是"这个瞬间的爆点浓度"。要改成测"这段作为独立视频的娱乐传播价值"，需：
- **维度去重**：hook 与 contrast 合并或划清界限（contrast 是"内容结构有反差"，hook 是"开头/标题能不能抓人"——hook 应该是**结果**（开头吸引力），不是**原因**（有什么反差）。避免同一瞬间双计分。
- **completeness 升权**：让"是不是完整事件"成为硬门槛而非边角料。
- **加反证/否决**：即便 hook/contrast 高，若 standalone 低（离开直播看不懂）或 completeness 低（没头没尾），不能进 S/A。S 应该极稀缺。

### (B) 拆分两个价值轴（回应你的 A/B 想法）
不建议急着做成两个完全独立的分数进 UI，但**必须在模型里区分**：

```
A. Propagation / 传播价值：发出去有没有人看、会不会传播
B. Archive / 素材价值：是否值得作为主播素材/档案保留（不一定要爆）
```

一个事件同时有 A 和 B：
- A 高 B 高 → 强高光（进 S/A）
- A 中 B 高 → 爆款边缘，值得做切片
- A 低 B 高 → 素材保留（生病网友），不该跟"娱乐爆分"混排
- A 低 B 低 → 淘汰

**最小落地（不推翻五维）**：在复审结果里加一个"价值轴"字段 `value_axis: propagation | archive | both | neither`，本地据此把事件分到不同轨道——`both`/`propagation` 走现有 S/A/B/C 娱乐排序，`archive` 单独进"素材库"（不参与爆款竞争），`neither` 进 D。这样生病网友这类能留素材但不占爆款位。

## 8. 纯 ASR 版本的能力边界（诚实版）

基于这次 51 分钟稿（文本错字多、大量重复碎片"许愿"x10/"我跳舞"x10）的真实观察：

**纯文本现在能做好**：
- 观点型/口播型高光（测评吐槽的"像纸盒""像墙皮"这类金句、知识输出、争议观点、清晰的事件叙述）
- 结构清晰的完整故事（主播讲了一个有起承转合的完整段子/经历）
- 语言驱动的反差/反转（说 A 结果做 B，且体现在台词里）
- 有明显台词的情绪爆发（大喊、惊人发言）

**纯文本天然做不好**（信息损失在 ASR 那一刻就注定）：
- **视觉型娱乐**：主播跳舞/整活/表演、表情变化（突然停顿/干呕/嫌弃脸）、商品变化（炸了/洒了/变色）、身体动作（吐掉/比划）——这次稿子里"我跳舞"刷屏，纯文本根本不知道跳得怎样
- **音频型信号**：笑声（观众/主播）、语气、停顿节奏、音量突升、BGM/音效——"这段很好笑"往往靠笑声，文本里没有
- **非语言冲突**：主播和观众的戏剧性若主要靠画面/声音节奏而非台词
- **ASR 错误污染**：错字（"汤诚衣品/大衣阁/淑于孙"）让事件理解和纠错都难

**结论**：这套系统对"口播型、语言强驱动"的娱播能到可用的程度；对"视觉/表演/节奏驱动"的娱播，纯文本顶多算"弱提示"，给不了可靠判断。**这不是加关键词能解决的，是模态缺失。**

## 9. 多模态长期架构（只设计，不实现）

建议未来走"多模态特征层 → 时间轴融合 → 事件理解"，而不是"把整段视频扔给多模态大模型"（后者贵且不可控）：

```
                    ┌─────────────────────────────┐
  视频/音频          │     特征层（各自轻量、各自对齐到秒） │
   │                ├─────────────────────────────┤
   ├──► ASR 文本     │  台词 / 词典+语义纠错               │
   ├──► 关键帧采样    │  视觉事件（表情/动作/商品变化/画面）    │
   ├──► 音频特征      │  情绪曲线(笑声/音量/停顿/语速)        │
   └──► (可选)字幕     └──────────────┬──────────────┘
                                     │  统一时间轴融合成 "多模态事件段"
                                     ▼
                        Event Understanding（事件理解，可在这一步用大模型，
                        但输入是"已对齐的多模态事件段"而非原始视频）
                                     ▼
                        Clip Worthiness + 剪辑边界
```

原则：
- **多模态进"特征层"补充事件信号**，不是替代文本理解
- 各类信号都先转成"带时间戳的事件线索"（如 [42:13] 表情突变 / [42:15] 笑声 / [42:16] 说"难吃"），在同一时间轴融合
- **融合后的"事件段"再进现在的 Event Judge/Review**——尽量复用现有事件框架
- ASR 是主骨架（事件/台词的语义主干），视觉/音频是"确认/补强"（把纯文本以为普通的 20s 重新标注为"笑声+表情突变=真爆点"）

## 10. 最小修改方案（不推翻 Step1/2/3，不重写）

按依赖与风险从小到大排序。**每步独立可测、可回退**。

### 阶段 A：先把"碎片→事件→复审"链路补结实（救 D 误杀 + 短事件碎片）
**A1. 修去重边界 bug（2 字符）**
`_same_event_identity` 用 `overlap_ratio>0.5 and topic>0.5` → 改 `>=`。救微波炉式"同一瞬间被报成两个候选"的重复（已实测确认是 bug）。

**A2. split 碎片不"失忆"**
`_make_event(split=True)` 不再置空 summary/structure。改为：复用簇上下文 + 该碎片原文，复审时若该事件无 structure，先让 AI"试着还原这个事件若独立存在的大致 setup/发展/payoff"，还原不了就标 `event_incomplete` 并触发扩窗，而不是直接对孤句打分。

**A3. D 级四分（真没价值 / 上下文不够 / 事件不完整 / AI 不确定）**
复审结果加字段 `reject_kind`（真淘汰才填）：
- `truly_low_value` → 允许 D
- `context_insufficient` / `event_incomplete` → 触发扩窗重审（已有通道），扩完仍不足 → 降 C 留候选池，**不判 D**
- `ai_uncertain` → 不判 D，回退海选分×保守系数兜底到 B/C，标"请人工复核"
reject_reason 改成由本地按 reject_kind 组装，不让 AI 现编"画面散乱"这种把困惑当缺陷的套话。

### 阶段 B：让海选知道它在找"事件"而不是"梗"（治短偏好源头）
**B1. 海选 prompt 加"候选粒度"约束**（不动打分逻辑，只改一句话引导）：
"候选应该是一个**能独立成立的事件单元**（可短到 10s 的一句话梗，也可长到 1-3 分钟带铺垫→发展→结果的完整事件）。当一个完整事件（开包→试吃→变脸→吐槽→吐掉）横跨较长时间时，请报成**一个**候选覆盖整段，不要拆成多个只抓爆点的短句。"
→ 让海选候选从"爆点句"变"事件段"，聚合层才有料可聚。

### 阶段 C：校准"什么值得拿高分"（救 S 高估 + B/C 混杂）
**C1. 维度去重 + 重权**：hook 与 contrast 在打分定义里划清界限；completeness 升权。建议权重（你拍板）`hook25/contrast20/persona20/standalone15/completeness20`。
**C2. 反证/否决**：本地加——standalone < 某线 或 completeness 明显低 或命中"依赖上下文"负面 → 即便加权够 S/A 也封顶 B。**S 变成稀缺档（本地再限：全场 S 最多 N 个）。**
**C3. 复审打分锚改写**：明确告诉 AI——一个完整事件（哪怕铺垫长）的 hook 可以高于一句俏皮话，因为它的悬念有结构支撑；一句没独立故事的俏皮话，standalone/completeness 应主动压低。让"完整事件"在子分上赢，而不是靠权重硬掰。
**C4. 推荐措辞修正**：删"payoff 一完就收/别拖无关"，改"若 setup 是笑点/反差的前提必须保留；完整事件优先给覆盖完整结构的最短范围"。加长事件 rec 复核：事件≥90s 且 rec<事件1/3 → 扩窗重问一次。

### 阶段 D：价值轴拆分（可选，验证 C 后评估）
复审加 `value_axis`（propagation/archive/both/neither），archive 单独进"素材库"不占爆款位。**先不做 UI，只把字段存下来观察**，等 C 稳定后看数据是否支持拆轨。

## 11. 修改后的验收标准（可人工验证）

每步改完，用同一份 51 分钟稿真实跑一遍，人工对照视频逐条验收：
1. **S 稀缺**：一场 S 级 ≤1-2 个，且人工认可"确实是全场最值得剪"。**不再出现"一句俏皮话轻松 A/S"。**
2. **B/C 分层**：B 里应是"值得剪的真事件"，C 里是"一般/素材"，人工能看出 B 明显好于 C。
3. **D 误杀下降**：微波炉那类"AI 没看懂但实际好玩"不再直接进 D；D 的 reject_reason 明确是"真没价值"而非"AI 困惑"。
4. **完整事件不被压成十几秒**：罐头/测评这类应出现 **1-3 分钟完整高光**，且 recommended 覆盖完整 setup→payoff。
5. **短事件仍可 8-15s**：真的一句话梗仍能保持 8-15s，不因规则被硬拉长。
6. **全时间轴覆盖** + 无前半段偏置（前后段事件数/质量均衡）。
7. **不把 AI 不确定直接当 D**（有"请人工复核"的中间态）。
8. **回归**：Step1 23/23、Step2 21/21 不回退；Step3 现有测试不回退，必要时新增（A1 去重边界、A3 reject_kind、B1 海选粒度、C2 反证、C4 长事件复核各加断言）。
9. **人工命中率**：人工认为值得剪的 TOP6（这次人工圈出的），AI 应能覆盖 ≥5 个，且不再把一堆"没意义"的塞进高分区。
