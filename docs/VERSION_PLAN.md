# VERSION_PLAN —— 版本规划

## v0.3.2（当前版本）—— 高光判断优化（评分体系 v3）

**要解决的核心问题**：v0.3.1 真实复测发现 AI 仍在当「直播总结助手」——事故型片段（饮料粉洒出来、军粮份量少）被评 A 级，部分 B 级反而更有短视频潜质。判断标准要从「发生了什么」换成「**陌生用户刷到为什么要停下来**」。

### 已完成（离线自测 18/18 过）✅
- 评分模型 v3：五维全换——三秒吸引力 30 / 反差意外 25 / 人物表现力 20 / 独立成片 15 / 事件完整度 10（D-022，删情绪/争议等「热闹度」维度）
- **本地定级引擎**：复审 AI 只打五维子分，总分本地加权、等级本地定（S/A/B/C/D），杜绝「先给理由再顺手打高分」
- **负面清单硬约束**：普通失误/普通展示/单纯惊讶/依赖上下文/普通评价 → 命中即本地封顶 B 级，进不了 S/A（D-023）
- 分级体系 A/B/C/D → **S/A/B/C/D 五级**（S≥9/A≥8/B≥6/C≥5）；自动精选只出 S/A（D-024）
- 复审必答双理由：why_cut（为何停留+传播点）/ risk（最大风险，禁写「无」）
- 典型案例校准写进提示词（黄腐鸡误当咖啡 / 军粮像纸盒子 高价值；饮料粉洒 / 哇好少 低价值）
- UI：S/A/B/C 徽章 + 五维判决书 + 封顶警示

### 待验收 🔨
- 真实视频人工命中率测试（用户准备素材中）：娱乐/游戏/知识 3 类各标 10 个值得剪片段，观察——AI 推荐 ≈ 人工剪辑师选择 的重合率；事故型片段是否不再进 A；B 级里翻出真爆点的能力
- 后续小版本候选：时间重叠候选合并（49:46 出现两个相似候选）、D 级≥3 自动重审、S 级数量上限等附加保险丝（本轮刻意未做，避免规则叠加无法归因）

## v0.3.1 —— 高光识别准确率优化（已完成 ✅）

**要解决的核心问题**：P0 真实 API 首测 0 推荐（人工复盘推翻）——候选生成漏掉大量潜在高光 + 复审过滤过严。策略从「严格筛选」转为「**先保证召回率，再保证精准率**」（D-017）。

### 已完成（离线自测 14/14 过）✅
- 海选召回优先：每区块至少 1 候选、宁多勿少、三问降为加分检查
- 三类高光：事件型 / 情绪型 / 梗型（各带专属评分维度）
- 评分权重 v2：传播 30 / 情绪 25 / 主播特色 15 / 争议讨论 15 / 独立成片 10 / 内容 5（D-020）
- 复审分级 A/B/C/D + 零输出禁令（全灭时最佳候选 ≥4 分强制保留 1 个 C，D-018）
- 漏检质检层：本地区块摘要 → 质检 AI 查漏 → 可疑区块重扫去重并入（D-019）
- 精细模式预算 5 万→8 万，不压缩 token 换准确率（D-021）
- clip_id：所有候选有唯一编号（未来 👍/👎 反馈记账）

### 收尾（已转入 v0.3.2）
- ~~真实 API 复测 51 分钟稿~~ ✅（2026-09-09，¥0.19：候选池 36 个、质检查出 2 个漏检区块、7A/19B/10C 分级、上版漏掉的爆点全部召回、不再零推荐）
- 人工标注测试 → 转入 v0.3.2 待验收（判断标准随评分 v3 升级为「AI 推荐 ≈ 人工剪辑师选择」）
- 已知遗留 → 记入 v0.3.2 后续小版本候选：重扫候选与原候选可能时间重叠（去重目前只按起止时间精确匹配）；候选池 36 略超 30 目标上限

## v0.3 —— 多阶段高光分析系统

**要解决的核心问题**：v0.2 的三个病——6000 字截断丢后半段、LLM 开头注意力偏置、「找重要内容」而不是「找值得剪的短视频内容」。

### Phase 1：纯本地分析层（零成本）✅
- transcript_parser / event_scanner / chunker / 用户词库
- 验收：时间轴 100% 覆盖（已过）

### Phase 2：AI 判断升级（核心）✅
- AI 海选（每区块独立，运营视角，候选解释三问）
- AI 复审（淘汰机制：recommend / reject_reason）
- AI 分析报告（总结 / 最强传播点 / 整体评价 / 为什么没推荐更多）
- Token 三模式 + 三级降级；数量三模式
- 验收：离线自测全过 + 真实 API 实测完成（2026-09-09，¥0.09，硬指标全过：被拒候选 / 无前半段偏置 / 覆盖 100%；0 推荐问题由 v0.3.1 处理）

### Phase 3：直播类型模型 + UI 接入 ⬜
- UI 三设置：直播类型 / 分析模式 / 数量模式
- 新结果卡片（新字段：viral_probability / emotion_score / conflict_score / editing_advice / confidence）
- 👍/👎 反馈按钮写 feedback.jsonl（v0.3 只攒数据）
- 户外 / 带货词库打磨
- 验收：切换直播类型结果确实不同

### Phase 4：三类直播实测 ⬜
- 测试集：6 分钟短视频 / 20 分钟视频 / 50 分钟以上直播
- 验收：时间轴完整覆盖、无前半段偏置、能主动拒绝垃圾候选、类型判断有区分、人工一致率提升

### 开发优先级（规范 v1.0 第十三节）

| 优先级 | 任务 | 理由 |
|---|---|---|
| **P0** | 真实 AI 复测（v0.3.1 精细模式）+ 人工标注测试（3 类直播各标 10 个，目标召回 >70% / 精准 >50%） | 验证召回优先策略是否真的降低误杀 |
| **P1** | 文本纠错系统第一阶段 | 输入质量决定 AI 判断上限（优先级由 v0.4 提前，见 D-014） |
| **P2** | UI 完善 | 直播类型 / Token 预算 / 数量模式 / 预计消耗展示 / 词库管理页面 |
| **P3** | 云端 AI 接口 | 降低用户电脑配置要求（架构见 D-013） |

### 每次新增功能前的四个问题（规范 v1.0 最终原则）

1. 是否提升高光判断准确率？
2. 是否降低使用门槛？
3. 是否增加商业价值？
4. 是否会造成未来维护困难？

回答不清楚的，不开发。
