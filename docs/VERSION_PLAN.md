# VERSION_PLAN —— 版本规划

> 状态标记：✅ 完成 / 🔨 进行中 / ⬜ 未开始 / ⏸ 推迟

## v0.4（当前版本）—— 从「找到哪里有东西」到「理解这件事值不值得剪」🔨

**要解决的核心问题**：v0.3 已经能找到爆点了（100% 覆盖 + 召回优先 + 质检重扫），人工复盘暴露的新瓶颈全部集中在同一件事——**AI 在评价一句话，而剪辑师在评价一件事**：
1. 找到很多候选，但排序和推荐不符合人工判断
2. 一个完整事件被拆成多个碎片（打开包装 / 发现份量少 / 吐槽像纸盒 → 三个低价值候选，合起来才是爆款）
3. 上下文太短，AI 看不到前因后果——单看普通、放在完整故事里很有价值
4. S/A/B/C 等级表达不了剪辑价值
5. 固定时长限制（提示词里写死「30 秒 ~ 3 分钟」）不符合真实剪辑逻辑

**v0.4 一句话**：不加大量新功能，只做一件事——**让 AI 从寻找片段，升级为理解完整事件并判断传播价值**（D-025）。

### 五条主线（需求全貌）

| # | 主线 | 做法 | 状态 |
|---|---|---|---|
| 1 | 事件聚合层 | 候选 → 事件合并 → 评价整个事件（event_id / event_summary / event_steps / main_hook / candidate_clips） | ✅ 步骤 2（19 候选→16 事件，真实 API 验证） |
| 2 | 上下文窗口 | 核心片段 ±60 秒；AI 判断是连续事件则扩到 ±3 分钟甚至整个事件（取代现在 600 字符上限） | ✅ 步骤 3（事件边界±60s 起步，扩 ±180/±300，与剪辑时长分离 D-038） |
| 3 | 动态时长 | 取消固定长度，AI 输出 recommended_duration（10 秒~5 分钟）+ duration_reason | ✅ 步骤 3（AI 输出 recommended_*，本步未设 5 分钟硬上限，最短 8s 实测） |
| 4 | 100 分制 + 四档 | 开头吸引力 25 / 故事完整度 25 / 人物表现力 20 / 反差意外 20 / 独立观看 10；强推荐 85+ / 推荐测试 70-85 / 素材库 50-70 / 不推荐 <50 | ✅ 步骤 3（内部仍五维 30/25/20/15/10 子分 1-10，本地加权 ×10 得 100 分；S≥90/A≥80/B≥60/C≥50/D<50 淘汰 D-036） |
| 5 | 事件重复合并 | 时间重叠 > 50% 且主题相同 → 自动合并 | ✅ 步骤 2（_dedupe_events 事件级去重） |

### 四步实施计划（用户已确认顺序与聚合方案）

| 步骤 | 内容 | 成本影响 | 状态 |
|---|---|---|---|
| 1 | **词库纠错（custom_dictionary.json）+ 反馈接口（feedback.json）** | 零成本纯本地 | ✅ 已完成（23/23） |
| 2 | **事件聚合层**：本地按时间粗合并 + AI 校正是否同一事件并写摘要/步骤 | 多 1 次调用 | ✅ 已完成（21/21 离线 + 真实 API ¥0.31） |
| 3 | 上下文窗口 ±60s + 动态时长 + 100 分制评分（复审架构改分批，因事件原文变长） | 上下文变长，成本上升 | ✅ 已完成（24/24 离线 + 真实 API ×2，¥0.31~0.34） |
| 4 | UI 接入（事件卡片 + 反馈按钮 + 词库管理）+ 5 项验收 | — | 🔨 下一步 |

**成本预估**：现在精细模式一场约 ¥0.19，v0.4 因上下文变长 + 多一次聚合调用，预计 ¥0.4~0.6。

**关键架构决策**：事件聚合采用「本地粗合并 + AI 校正」混合方案（D-026，用户拍板）——本地零成本预合并成事件簇，AI 只判簇不看完稿，成本可控。

### 验收标准（5 项，需求文档指定）
1. 同一个完整事件不能拆成多个低价值片段
2. 人工认为好的 B/C 候选应该进入推荐
3. 普通事故不能进入高推荐
4. 不同长度爆点（10 秒 / 1 分钟 / 5 分钟）都能合理判断
5. 人工选择 TOP10，AI 命中率明显提高

## v0.3.2 —— 高光判断优化（评分体系 v3）

**要解决的核心问题**：v0.3.1 真实复测发现 AI 仍在当「直播总结助手」——事故型片段（饮料粉洒出来、军粮份量少）被评 A 级，部分 B 级反而更有短视频潜质。判断标准要从「发生了什么」换成「**陌生用户刷到为什么要停下来**」。

### 已完成（离线自测 18/18 过）✅
- 评分模型 v3：五维全换——三秒吸引力 30 / 反差意外 25 / 人物表现力 20 / 独立成片 15 / 事件完整度 10（D-022，删情绪/争议等「热闹度」维度）
- **本地定级引擎**：复审 AI 只打五维子分，总分本地加权、等级本地定（S/A/B/C/D），杜绝「先给理由再顺手打高分」
- **负面清单硬约束**：普通失误/普通展示/单纯惊讶/依赖上下文/普通评价 → 命中即本地封顶 B 级，进不了 S/A（D-023）
- 分级体系 A/B/C/D → **S/A/B/C/D 五级**（S≥9/A≥8/B≥6/C≥5）；自动精选只出 S/A（D-024）
- 复审必答双理由：why_cut（为何停留+传播点）/ risk（最大风险，禁写「无」）
- 典型案例校准写进提示词（黄腐鸡误当咖啡 / 军粮像纸盒子 高价值；饮料粉洒 / 哇好少 低价值）
- UI：S/A/B/C 徽章 + 五维判决书 + 封顶警示

### 待验收 🔨
- 真实视频人工命中率测试（用户准备素材中）：娱乐/游戏/知识 3 类各标 10 个值得剪片段，观察——AI 推荐 ≈ 人工剪辑师选择 的重合率；事故型片段是否不再进 A；B 级里翻出真爆点的能力
- 后续小版本候选：时间重叠候选合并（49:46 出现两个相似候选）、D 级≥3 自动重审、S 级数量上限等附加保险丝（本轮刻意未做，避免规则叠加无法归因）

## v0.4.5 —— 修复本地 ASR 错误处理链路（分层提示 + 模型离线加载）✅（2026-09-11 完成）

- **修复**：网页版对**任何**上传视频都统一提示「视频处理失败，请换一个文件试试」，正常视频也被当成"视频损坏"
- **根因**：① 加载本地 Whisper 模型时会经 huggingface_hub 做远程校验，本机代理返回 **502 Bad Gateway** → 正常视频也失败；② `extract_audio`/`process_video` 失败只 `return None`，信息被丢弃 → 所有失败塌缩成同一句
- **新增**：`errors.py`（带 stage 的 `ProcessError`）；`check_video_readable()` / `probe_media()`（ffmpeg 探测可读性与音轨）；UI 十条分层文案
- **核心改动**：模型**离线优先加载**（`local_files_only=True`），只在缓存没有该模型时才联网下载
- **现在能区分**：媒体文件无法读取 / 未检测到音轨 / 音频提取失败 / FFmpeg 不可用 / 缺少依赖库 / 本地模型未安装 / 模型加载失败 / 语音识别推理失败 / 没有识别出内容
- **开发者可见**：完整 traceback + 原始错误 + 控制台输出（不再被吞）
- 测试：test_v045_asr_errors **18/18**（7 种情况 stage 互不相同）+ 真实 6 分钟视频 41 句成功识别（详见 D-046）
