## 1. 当前问题诊断（基于 B1 结果 + 人工复核）

### 1.1 B1 结果统计

| 指标        | 数值                 |
| --------- | ------------------ |
| 候选数       | 38                 |
| 事件数       | 18                 |
| 单候选碎片     | 9/18 (50%)         |
| ≤28s 碎片   | 4 个                |
| >60s 完整事件 | 8 个                |
| 等级分布      | A1 / B11 / C3 / D3 |

### 1.2 人工复核关键发现

- **D级误杀 3 个**：ev-017/008/013（短梗金句，AI判D但用户认为有价值）
- **A级高估 1 个**：ev-005（13s碎片，"不完整不到A"）
- **事件不完整**：ev-002（269s"非全过程"）、ev-012（142s"太短不完整"）
- **碎片应合并**：ev-005/006 同区应合并

### 1.3 根因分析

当前 Event 聚合层的问题：

1. **缺乏宏观上下文**：AI 直接处理碎片候选，没有"这场直播在讲什么"的整体认知
2. **聚类粒度粗糙**：基于时间+主题关键词，容易把不同内容混入同一簇
3. **上下文窗口固定**：±60s 无法适应长事件（如罐头测评需 5-10min 上下文）

## 2. Story Layer 设计方案

### 2.1 层级结构

```
整场直播 (Transcript)
    ↓ AI一次性理解
Chapter 1: 罐头测评 (0-15min)
Chapter 2: 整活互动 (15-30min)
Chapter 3: 晚餐/游戏 (30-51min)
    ↓ 每章独立Event聚合
Story A: 拆军粮 (0-5min)
Story B: 试吃反应 (5-10min)
Story C: 罐头异物 (10-15min)
    ↓ Event聚合+复审
Event 1: 开包装发现份量少
Event 2: 试吃吐槽像纸盒
Event 3: 发现异物夸张反应
    ↓ Highlight筛选
Highlight: 最佳剪辑片段
```

### 2.2 Story 判断逻辑

- **输入**：完整 transcript 前 N 分钟（建议 10-15min 滑窗）
- **输出**：
  - `story_id`: 唯一标识
  - `name`: 一句话描述（如"拆美军口粮"）
  - `start/end`: 时间边界
  - `candidates`: 该故事内的候选列表
- **软边界**：Story 边界是概率性的，Event 聚合时可跨 Story 取上下文

### 2.3 实现方式

- **离线 PoC**：`poc/story_layer.py`（独立文件，不改主流程）
- **AI 调用**：1次/10min 滑窗，约 1500 token/次
- **总成本**：51分钟 ≈ 5-6次调用 ≈ 7500-9000 token

## 4. 与 B1 对比分析

| 维度         | B1 当前      | Story Layer    | 改善         |
| ---------- | ---------- | -------------- | ---------- |
| 事件碎片率      | 50% (9/18) | ~20% (预估)      | 降低 30%     |
| 完整事件(>60s) | 8/18 (44%) | 预估 10/15 (67%) | +23%       |
| D级误杀       | 3个         | 可减少（有上下文）      | 改善         |
| A级高估       | 1个         | 可减少（完整故事）      | 改善         |
| Token成本    | 现有         | +7500-9000     | +¥0.05-0.1 |

### 4.1 预估收益

1. **事件完整性提升**：AI 先理解"这场在讲什么"，Event 聚合时有宏观上下文
2. **碎片减少**：同 Story 内的候选更易被合并
3. **评分准确**：长事件有完整 context，评分更合理

### 4.2 风险

1. **AI 判断误差**：Chapter/Story 划分可能不准（软边界缓解）
2. **成本增加**：约 +¥0.05-0.1/场
3. **延迟增加**：多 1-2 分钟处理时间
