# Audio Signal 层级重审 —— 三层分离架构（2026-09-09）

> 触发：用户复核 Audio PoC Top25 后（y=13/n=12）指出关键风险——高能量/ZCR 异常可能只是
> 装修、碰撞、BGM、礼物音效等环境声，**不能直接视为高光**。
> 本文：纯分析 + 最小安全架构 + PoC 改造方案 + 验收指标。**不改主流程、不接入评分。**

---

## 一、核心定位修正

Audio 在本系统里**永远只是 evidence（证据），不直接决定 highlight_value**。

必须明确三个彼此独立的概念层级：

| 层级 | 是什么 | 由谁判断 | 用途 |
|---|---|---|---|
| **audio_anomaly** | 纯信号层面的"能量/ZCR 偏离基线" | 本地 DSP（numpy/ffmpeg） | 候选提示（"这里声音有动静"），不承诺是啥 |
| **audio_event** | 语义层面的"可能是笑声/尖叫/碰撞/BGM/人声" | 未来 YamNet / speech 检测 | 过滤误报，给出"这是哪类声音" |
| **highlight_value** | "这段值不值得剪" | **ASR + Event + 未来 Vision** | 真正的剪辑价值判断 |

**关键铁律**：audio_anomaly 和 audio_event 都只是**给上层提供"这里有值得看一眼的声音证据"**，能不能成高光，必须由文本/事件语义层最终裁决。Audio 提升的是**召回**（别漏掉声音型高光），不提升**精准**（不背"这是高光"的书）。

## 二、现有降级版 PoC 的检测缺陷（实测证据）

现有 `poc/audio_hotspot_detect.py` 的问题，我用 51 分钟真实音频实测逐条验证：

### 缺陷 1：绝对能量阈值，非相对环境基线
- `ENERGY_ABS_MIN=0.10` 是绝对下限。直播有持续 BGM/底噪时，几乎所有帧都过线。
- 实测：51 分钟里 **87.6%（2715s）有人声**，整片音量持续在阈值之上。

### 缺陷 2：突发判断只比"前 2s 局部中位"，不比较全场基线
- `is_burst = rms[i]/median(前2s) > 2.5`。主播**说话本身起伏就大**，2.5x 轻易触发，把普通说话当成"突发"。
- 这是能量 burst 高达 301 个（几乎每 1-2s 一个）的直接原因。

### 缺陷 3（最致命，实测）：ZCR 在有人声直播里无区分力
对比三类点的 ±1.5s 窗口特征（E=能量峰值，ZCR=过零率峰值）：

| 类别 | E 峰值范围 | ZCR 峰值范围 |
|---|---|---|
| **y（人工确认真情绪）** | 0.175 - 0.355 | 0.236 - 0.590 |
| **n（人工确认误报）** | 0.155 - 0.375 | 0.275 - 0.543 |
| **普通说话基线** | 0.154 - 0.376 | 0.300 - 0.622 |

**三类完全重叠，无法用能量或 ZCR 区分。** 甚至普通说话（37:42 ZCR 0.578、34:35 ZCR 0.622）比很多真笑声点 ZCR 还高。

> **结论**：在"主播持续说话"的直播间（87.6% 时间有人声），绝对能量和 ZCR 只能告诉我们"这里响/这里有高频"，**区分不了笑声 vs 说话 vs BGM**。Top25 能挑出 13 个 y，更多是靠"文本弱"筛选维度 + 人工听判，能量/ZCR 本身的判别力很弱。52% 命中率有较大侥幸成分。

### 缺陷 4：无 speech overlap / 人声判断
- 当前不做"此刻有没有人声"分离。实测误报大多**发生在有人声段**（说话中的突发音量/高频/音效混响），所以"按有无文字分段过滤"只能砍掉 5% 的误报（纯 BGM 段），**帮不上主要误报**。

### 缺陷 5：三档 kind 是"信号组合"不是"语义分类"
- energy_burst / high_freq_burst / strong_anomaly 只是"能量×ZCR×突发"的布尔组合，被命名成疑似笑声/尖叫，**但没有任何语义依据**——装修碰撞、BGM 鼓点同样满足 strong_anomaly。

## 三、三层分离的最小安全架构

```
原始音频 (16k 单声道 WAV)
   │
   ├─[L0 预处理]─────────────────────────────────────────┐
   │  1. 算整场/长窗能量分布 → 环境基线(E_base)          │
   │  2. 算帧级 RMS、ZCR                                │
   │  3. (可选)简单人声活动检测(VAD) → speech_mask      │
   └────────────────────────────────────────────────────┘
   │
   ▼
[L1 audio_anomaly]  ---- 只产"证据"，零语义
   判定 = 相对基线突变(非绝对)
     - 帧能量 > max(E_base × K1, 绝对下限)     相对环境基线
     - 且/或 能量突增 相对"更长基线窗"(≥8s)     持续vs突发
   → 时间戳片段列表 (start/end/energy_ratio)
   │
   ▼
[L2 audio_event]   ---- 语义分类，过滤误报
   - speech_mask 重叠 → "说话中"(与L3弱化联动)
   - YamNet(网络恢复后) → laughter/scream/... 标签
   - 启发式代用(当前网络) → 只能标"疑似情绪"置信度低，不硬判类型
   → 每个 anomaly 附: 人声重叠? / 疑似类型 / 置信度
   │
   ▼
[L3 highlight_value] ---- 由 ASR+Event 语义层裁决(不是Audio)
   Audio 只贡献: "这段有 {audio_event 证据}" 作为事件候选/评分旁证
   最终是否高光 = 文本事件理解说了算
```

---

## 四、关键改进点（相对现有实现）

1. **相对环境基线，不看绝对音量**：先算**整场/分段长窗的能量分布**做基线 E_base（如每 60s 窗口的 p85 分位），突发判定改为 `rms[i] > max(1.5 × E_base_local, E_abs_min)`。这样"直播间本底就吵"不会被全场触发，只有**明显盖过该时段环境的**才算 anomaly。

2. **speech overlap 判断**：接入一个轻量 VAD（16k 单声道，本地可做：能量门限 + 谱平坦度近似，或用 ASR 已有的 silence 段）。把 anomaly 标成"说话中" vs "非说话(纯声音)"。**说话中的 anomaly 更可能是情绪反应(笑声打断说话)，非说话段的高 anomaly 更可疑(BGM/装修)**——但注意实测两者 ZCR 无差，所以 speech 只能当**权重线索**不能当判定。

3. **突发 vs 持续环境噪声区分**：比较**更长基线窗(≥8s)**而非前 2s。持续 BGM 会让 8s 基线也高，突发爆点则会明显高于它。加**持续时间约束**：真笑声/惊呼通常 0.3-2s，持续 >4s 的高能更像音乐/持续噪音。

4. **明确误报来源**：BGM(音乐性，谐波规则、能量平稳)、礼物音效(短促、高频、重复)、碰撞(极短 <0.15s 高能脉冲) → 可作为后续启发式粗筛，但**最终靠 YamNet 语义**解决。

5. **未来替换路径**：L2 的"启发式 audio_event"设计成**可插拔**——同样输出 (start/end/type/confidence) 结构，网络恢复后把 YamNet 推理结果直接喂进来，不动 L1/L3。

## 五、最小 PoC 改造方案（独立文件，不改主流程）

新增 `poc/audio_layers.py`（或改造现有 audio_hotspot_detect.py 成层化输出），验证三层分离是否降低误报：

**输入**：poc/t2.wav（已导出）+ transcripts/测试视频2.txt

**L0**：整场能量分位基线 → 每 60s 局部基线 E_base(t)；帧级 RMS/ZCR。
**L1**：相对基线 anomaly 检测（1.5×局部 p85 基线 + 3-8s 长窗突增约束 + 0.3-4s 时长窗）→ 输出候选 anomaly（预计比现在 541 个大幅减少）。
**L2**：给每个 anomaly 打 speech 标签（ASR 文字稿该时刻有人声=说话中/无=非说话）+ 简单类型粗标（short_pulse 碰撞 / sustained_highE 疑似BGM / high_zcr 疑似情绪），**type 只作参考不做硬判定**，confidence 都给低值标注"启发式"。
**L3**：输出一份**对照表**——每个 anomaly 与 A3 事件、与 Top25 人工标注的 y/n 对齐，统计：
- 新检测 anomaly 是否保留住 13 个 y（**召回不能掉**）
- 12 个 n（误报）是否被 L1/L2 过滤掉（**误报下降**）
- 相对现有 541→ 减少到多少

**不改主流程、不接评分、不加任何现有逻辑。**

## 六、验收指标

| 指标 | 目标 | 对比基准 |
|---|---|---|
| y 点召回 | ≥11/13（保住大部分真情绪） | Top25 人工标注 |
| n 点（误报）过滤 | 从 12 降到 ≤6 | Top25 人工标注 |
| anomaly 总数 | 从 541 大幅降到 <200（稀疏化） | 现有 audio_hotspots.json |
| speech 标签正确率 | 人工抽查 ≥80% 一致 | 对照 ASR 稿 |
| 主流程/A1/A2/A3/评分 | **零改动** | git diff |
| 运行成本 | 纯本地 numpy，≤2 分钟 | 与现有持平 |

**说明**：目标不是"AI 打分更准"，而是验证——**在加一层"相对基线 + 语义粗分 + speech 感知"后，能否用更少的 audio_anomaly 覆盖同样的真高光（y），同时显著砍掉误报（n）**。只有这步成立，才值得等网络恢复后接 YamNet 做真正的语义分层。

## 七、清醒边界（必须承认）

1. **纯能量/ZCR 在有人声直播里无法区分笑声 vs 说话**（本审计实测铁证）。三层分离能**减少误报、保留召回**，但**永远无法替代 YamNet 的"这是笑声"语义判断**。L2 的启发式 type 只是过渡。
2. **audio 只能补"情绪/行为型"高光**（笑/叫/炸/碰撞反应），补不了"需要懂梗/前后文的故事型"——后者还得靠 ASR 事件理解。
3. **视觉信号（表情/动作/呕吐画面）本次不在范围内**，是 Audio 之后的另一个模态。
4. Audio 的**最终价值 = 提升候选层的召回**（让"文本看着普通、但实际有反应高潮"的段能进事件池），评分是否加权是 Step 3.2 之后的事，本次不做。
