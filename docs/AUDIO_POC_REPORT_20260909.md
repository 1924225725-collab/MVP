# Audio PoC 降级版报告（阶段 1）：本地信号检测"音频异常热点"

日期：2026-09-09
性质：**独立 PoC，未接入主流程**，未改 A1/A2/A3 / pipeline / prompt / 评分 / UI
样本：`videos/测试视频2.mp4`（51:40，与 A3 人工复核同一场）
输入：ffmpeg 重导出的 16kHz 单声道 WAV（`poc/t2.wav`）
说明：YamNet 因 GitHub/HuggingFace 网络不可达未下载，本版用**纯本地 numpy 信号处理**检测"音频异常"，不判断具体是笑声还是尖叫。

---

## 一、方法（做了什么）

对 51 分钟音频，滑窗 100ms 逐帧算：
- **RMS 能量**（音量）
- **ZCR 过零率**（高频/噪声/笑声指示）
- **能量突增**（相对前 2s 中位数 >2.5x）
- 组合成三类热点：
  - `strong_anomaly` = 高能 + 高ZCR + 突增（最疑似笑声/尖叫/惊呼/干呕）
  - `high_freq_burst` = 高能 + 高ZCR
  - `energy_burst` = 纯能量突增

每个热点与**文字稿**对照：该时段 ASR 抓到几个词（`text_density`），0-8 词=「文本弱」。

## 三、初步价值判断（需人工复核确认）

1. **能量维度与真高光有相关性**（阶段 1 能量版已验证）：最强"停顿后爆发"29 个里约 15 个落在 A3 已确认的 A/B 高光事件内（微波炉 ev-017、罐头 ev-014、米饭 ev-016 等）——说明音频能量确实在高光点有爆发。
2. **音频强文本弱 ≠ 全部是漏检**：155 个里 72 个其实在 AI 事件区间内（系统抓到了但没靠文本词），真正"完全在事件外"的 83 个才可能是漏检候选。
3. **83 个候选需人工听**：降级版无法区分"真笑声/尖叫" vs "BGM 鼓点/环境音/主播大动作声"。已生成复核清单（文本词数最少 + 能量最高的优先）。

## 四、误报类型（降级版的明显局限）

- **BGM 鼓点/节奏**：直播间常有背景音乐，重拍会被 ZCR/能量当 high_freq/strong
- **环境噪声/碰撞声**：拆包装、金属碰撞、桌椅响动等高能瞬态
- **主播大嗓门/喊麦**：纯音量高但可能只是说话大声，非情绪爆发
- **点击/特效音**：直播间的礼物音效、提示音
> 这些都是"有能量但非笑声/尖叫"的假阳性。**降级版只能提示"这里音频异常"，无法确认"是人声情绪爆发"。**

## 五、是否值得接入正式音频模型？

**结论：值得，但接入的是"语义级音频事件分类"（如 YamNet 笑声/尖叫/咳嗽），不是本降级版启发式。**

理由：
1. 降级版已证明**音频维度有增量信号**（能量高光与真高光相关 + 能找出 83 个文本系统外候选）——音频值得做。
2. 但降级版**误报率太高**（BGM/环境音无法区分），直接用于评分会污染。需要一个能说"这是笑声/尖叫"的模型来过滤。
3. 下一步路径（待网络可下模型后）：YamNet ONNX（笑声/尖叫/咳嗽类）→ 只在能量热点附近跑（省算力）→ 用"音频事件类型"而非"能量异常"做评分旁证。
4. **本降级版结果不应直接用于高光评分**（误报不可控），只作为"音频候选热区"提示，供人工复核验证音频价值。
