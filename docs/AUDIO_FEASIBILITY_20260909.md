# Audio 可行性审计：纯文本 ASR 漏掉的娱播高光，能否用音频信号补充

日期：2026-09-09
性质：**纯分析，未改任何代码**
作者：Agent（晨曦）
范围：判断"哪些娱播高光能靠音频补上、怎么补、要花多少"，给最小 PoC 方案。

---

## 0. 审计前先厘清一个关键前提（决定整个方案走向）

**当前音频链路是为"语音识别"优化的，不是为"情绪分析"优化的。**

`pipeline.extract_audio` 把视频压成 **16kHz / 单声道 / MP3**——这是 Whisper 的标准输入。但它会丢掉大量音频情绪信息：
- 16kHz 砍掉了 >8kHz 的高频（笑声的"嘶哑/气声"成分、部分音色细节受影响）
- 单声道没了声场
- MP3 有损压缩进一步损失细节

**好消息**：原始视频（`videos/*.mp4`）还在，可以从头用 ffmpeg **无损/高保真重导出**任意格式。实测 ffmpeg 7.1 导出 44.1kHz WAV 速度 **661x 实时**（2s 音频瞬间完成）——重导出成本几乎为零。

**所以结论**：音频补充不用动现有 ASR 链路，而是**在 ASR 之外并行加一条"音频信号分析"支线**，从原始 mp4 重新导出高保真音频。

## 1. 本机已具备的音频能力盘点（实测确认）

| 能力 | 现状 | 说明 |
|---|---|---|
| ffmpeg | 7.1 完整版 | 原生滤镜可用：`volumedetect`（音量）、`astats`（能量/响度统计）、`silencedetect`（静音）、`ebur128`（响度）、`highpass/lowpass`（滤波） |
| numpy | 2.5.3 已装 | 能对导出的 PCM 波形做能量/过零率/帧级分析 |
| onnxruntime | 1.29.0 已装 | **关键**：可跑 ONNX 格式的轻量音频分类模型（本地推理，无需 TF/PyTorch）|
| librosa/scipy | 未装 | 精细音频特征库缺——但能量/响度这类基础特征 numpy 够，不强制装 |
| 原始视频 | 在 `videos/` | 可随时高保真重导出 |

**意义**：
- **基础能量/响度信号**：ffmpeg 滤镜 + numpy，**零新增依赖**就能做
- **笑声/哭声等"语义级"音频事件**：需 ONNX 音频分类模型，用已装的 onnxruntime 本地跑，不用装重库
- 结论：**本项目做音频补充没有技术障碍，且大多是低成本/本地方案**

## 2. 你要的信号：本地提还是用模型？（逐一判断）

### 2A. 明确可"本地低成本提取"（ffmpeg/numpy 就够，零新依赖）

| 信号 | 提取法 | 可靠性 | 局限 |
|---|---|---|---|
| **突然音量/能量突变** | ffmpeg `astats` 或 numpy 帧能量，算短窗能量相对前窗的跃升比 | 高 | 会混入主播凑近麦、拍桌等非情绪声 |
| **长停顿后突然爆发** | `silencedetect` 找停顿，接能量突增；或音量方差跳变 | 中-高 | 停顿也常是正常语速节奏，需结合时长阈值 |
| **整体情绪强度/话密节奏** | 话轮密度、平均响度、音量波动系数（方差/均值） | 中 | 区分"兴奋"和"单纯吵"需结合内容 |

这些**不需要模型**，ffmpeg 一行滤镜 + numpy 一段脚本就能产出"每秒一个信号值"的时间序列。是 PoC 的第一步，成本极低。

### 2B. 值得用"轻量音频模型"（onnxruntime 本地推理）

| 信号 | 模型类型 | 可靠性 | 依赖 |
|---|---|---|---|
| **笑声/爆笑** | 音频事件分类（如 YamNet 的 laughter 类，有 ONNX 版）| 高（笑声是音频事件里最可靠的） | onnxruntime(已装)+ 一个 ONNX 模型文件(~15MB) |
| **尖叫/惊呼** | 同上（YamNet 有 scream/squeal 类）| 中-高 | 同上 |
| **呕吐/干呕/咳嗽** | 音频事件分类（咳嗽 cough 类较常见；干呕/呕吐少见需自定义）| 咳嗽高/干呕低 | YamNet 无专门呕吐类，需找或自己训 |

**关键结论**：YamNet（Google 开源，224 类音频事件）能覆盖笑声/尖叫/音乐/咳嗽等，有现成 ONNX 转换版，**本地 onnxruntime 推理，无需联网、无需大模型**。这是"笑声/尖叫"这类信号最划算的方案——比纯信号处理可靠（能量突变分不清是笑还是拍桌），比上大模型便宜得多。

### 2C. 现阶段不建议碰的（成本/收益不划算）

- **细粒度情绪识别**（"主播是开心还是嘲讽"）：要模型、还不准，且对"是否值得剪"帮助有限
- **说话人分离**（区分主播/搭档/观众笑声）：多重，PoC 不需要
- **多模态大模型直接看视频**：贵、慢、不可控，违背"先本地低成本"

## 3. 音频信号怎么与现有 Event Model 融合（不改代码的思路）

现有链路：`Transcript → 海选候选 → 事件聚合 → 分批复审 → 评分`。

音频信号**不该进海选/复审的文本 prompt**（那会让 prompt 又长又不可控）。最干净的融合点是：**在"候选/事件"层，用音频信号给候选打"音频辅助标签"，作为评分的一个旁证**。

具体设计（3 个注入点，按优先级）：
1. **候选补充**（海选后）：对每个海选候选的时间窗，查询该时段的音频信号（"有没有笑声/尖叫/音量突增"），**作为候选的一个元数据字段**存下来。这样复审 AI 能看到"这个 20s 候选内有 2 处笑声 + 1 次音量突增"——纯文本以为是"主播说了句还行"，实际音频显示是全场最炸的笑点。
2. **事件边界校验**：事件聚合后，若某事件时间段内音频"高情绪密度"（笑声/尖叫集中），说明它是真高光，可提升 confidence；若事件长但音频平淡（无笑声无突变），可能被高估。
3. **评分旁证**（最轻，A2 门控类似思路）：不直接改五维分，而是输出一个 `audio_interest` 字段（0-1），供 UI/人工参考，或作为"是否进 A"的一个非硬性提示。

**融合原则**：音频是**旁证/补强**，不是替代文本判断。它补的是"纯文本看不到的行为/情绪爆发"，不覆盖"这段讲什么"的语义判断。

## 4. 最小 PoC 方案（本地、低成本，可独立验证）

### 阶段 1（先做，验证价值）
**目标**：只做"笑声/尖叫/音量突变"三信号，验证它们能否把纯文本漏掉的高光找回来。

步骤：
1. 对 `videos/测试视频2.mp4` 用 ffmpeg 重导出 44.1kHz 单声道 WAV（几秒完成）
2. 用 ffmpeg + numpy 算**每秒音量/能量曲线**，标出"能量突增 >3x"和"长停顿后爆发"时刻
3. 加载一个 ONNX 音频事件模型（YamNet ONNX），对音频做滑窗推理，标出"笑声/尖叫"时刻
4. 把这三类信号合成一个"音频高情绪时间轴"（标注秒级区间）
5. **对照现有文字稿**：找出"音频强烈但文本平淡"的区段（如主播在笑/尖叫但 ASR 只记了"嗯/还行"）——这些就是纯文本漏掉的高光候选

**预期产物**：一份"音频情绪热区表"（时间 + 信号类型 + 强度），人工对照原视频验证是否真的高光。

**成本**：
- 重导出：免费，几秒
- 能量分析：免费（ffmpeg+numpy）
- YamNet ONNX 推理：本地 CPU，51 分钟音频约 **5-10 分钟**（一次性）
- **总增量成本 ≈ ¥0（全本地），只需一次性下载 ~15MB ONNX 模型**

### 阶段 2（价值验证后）
把"音频情绪热区"与海选候选做时间对齐，输出"候选 + 音频旁证"表，给复审/AI 用。

### 阶段 3（验证有效才做）
接入现有流程（候选元数据 / 评分旁证），但那属于改代码，PoC 阶段先不做。

## 6. 验收标准（阶段 1 能回答的问题）

用 `videos/测试视频2.mp4`（51 分钟，本次 A3 用的同一场）验证：
1. **能找到 ≥5 处"音频强但文本弱"的区段**（笑声/尖叫集中在，但 ASR 文本平淡无亮点）——证明音频有增量价值
2. 人工对照原视频，这 ≥5 处里 ≥3 处**确实是高光**（音频高情绪≈真高光成立）
3. 纯文本高光（如"像墙皮"金句）**不受影响**——音频补充不是要替换文本判断
4. 计算量可控（51 分钟音频分析 ≤10 分钟，成本 ¥0）

## 7. Audio Signal Top 3（最值得先验证）

按"可靠性 × 增量价值 × 实现成本"排序：

### Top 1：**笑声（laughter）**
- 最可靠：YamNet 的 laughter 类非常准，几乎不会误报
- 增量最大：直播里"这段好笑"最强的信号就是笑声；纯文本常抓不到（大家笑成一团时没人说话）
- 成本最低：现成 ONNX 模型，本地跑
- **为什么第一**：它是"这段是不是真高光"的最强单一音频代理

### Top 2：**音量/能量突变（sudden loud burst）**
- 最通用：零依赖，ffmpeg+numpy 就能算，能覆盖尖叫/惊呼/拍桌/音乐爆发等多种"这里出事了"
- 增量大：主播突然大声（怒/惊/夸张）常是行为高光，文本可能只是同一句话但语气完全不同
- 成本最低：不下载任何模型
- **为什么第二**：覆盖面广 + 零成本，虽然会混入非情绪声，但作为"候选提示"够用

### Top 3：**尖叫/惊呼（scream/exclaim）**
- 可靠性中：YamNet 有相关类，比笑声略易误报（音乐、观众起哄可能触发）
- 增量大：惊呼是娱播重要高光（翻车瞬间/惊喜/惊吓），纯文本几乎必漏（ASR 记成"啊"或忽略）
- 成本低：同 YamNet
- **为什么第三**：增量好，但需跟音量突变协同（尖叫本质是"高音调+大音量"，可与 Top2 合并验证）

> **一个清醒的提醒**：这三者本质都在抓"**这里情绪/能量爆发了**"。它们擅长补"行为型高光"（笑、叫、炸），**不擅长补"需要懂梗/懂前后文的故事型高光"**——后者还得靠文本 + 事件理解。所以音频是**补强**不是**银弹**，PoC 的目标就是验证它能补多少。

---

## 8. 一个诚实的边界说明

音频补充解决的是你之前指出的"纯 ASR 漏掉视觉/行为"中的**声音部分**：
- 笑声、尖叫、音量爆发 → **音频能补** ✓
- 表情变化、动作、商品变化、画面梗 → 音频**补不了**（那是视觉/关键帧的事，本次明确不做）

所以音频 PoC 的定位：先补"声音情绪"这一块，验证值得后再谈关键帧。不要一上来做完整多模态。
