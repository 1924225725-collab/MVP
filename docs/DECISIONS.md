## D-001 为什么不用一次性把全文丢给 AI 分析？

**背景**：v0.2 就是这么做的（截断 6000 字 + 单次调用），结果：
- 长直播后半段直接丢失（截断）
- LLM 存在前半段注意力偏置，后面的内容容易被遗漏
- AI 的任务是「找重要内容」，不是「找值得剪的内容」

**决策**：采用多阶段流水线——分段分析 + 候选池 + AI 复审。
每段独立分析消灭位置偏置；复审层用运营视角淘汰，对齐「值得剪」的目标。

## D-002 候选信号扫描层为什么绝不过滤？

**原因**：直播高光可能来自突然事件、故事反转、情绪变化、甚至平静但有价值的观点。
词库只能测「热闹度」，测不了「价值」。
如果扫描层有权跳过区域，就会漏杀「平静但值钱」的片段。

**决策**：扫描层只调分析深度（热区细切 / 普通区粗切），所有时间段必须进入 AI 分析流程。
这条铁律写在 event_scanner.py 和 chunker.py 的文件头注释里，谁改谁负责。

## D-003 AI 的身份为什么是「运营」而不是「总结助手」？

**背景**：用户指出 v0.2 的 AI 像观众（「这个挺有意思」），但产品需要 AI 像运营（「这个发出去有人看吗」）。

**决策**：所有 v0.3 提示词的 system 身份统一为「拥有多年经验的直播短视频运营人员，任务不是总结直播内容，而是判断哪些片段值得剪辑发布」。海选必须回答三问：为什么用户会停留 / 为什么适合短视频 / 为什么不是普通聊天。

## D-004 为什么要有复审淘汰机制？

**背景**：海选容易放宽标准（AI 找候选时倾向于多给）。例：主播安慰粉丝——情绪价值高，但缺冲突、缺讨论点、外人没有观看动力、需要大量上下文，发出去没人看。

**决策**：复审层带淘汰权（recommend false + reject_reason[]），让 AI 学会拒绝「垃圾高光」。
判断口诀：**情绪价值 ≠ 传播价值**。同时复审要产出分析报告，向用户解释「为什么没推荐更多」——不解释，用户会以为 AI 没认真分析。

## D-005 为什么 Token 三模式不直接展示 token 数字？

**原因**：用户（最终使用者）关心的是效果、速度、价格，不是 token。暴露数字只会制造理解负担。

**决策**：UI 只显示模式名（快速/标准/精细）+ 预计时间/成本/精度描述。预算数字留在 config.py（TOKEN_MODES）。

## D-006 为什么数量模式叫「候选池」而不叫「全部」？

**原因**：「全部」暗示不加筛选地倾倒结果，用户会被垃圾候选淹没。

**决策**：候选池模式展示所有超过最低质量线（score ≥ 6，config.MIN_QUALITY_SCORE）的候选，且每个都带 AI 的 recommend 标记，用户自己权衡。

## D-007 为什么词库分三层（通用强词 / 类型词库 / 用户词库）？

- 通用强词：情绪爆发是所有直播类型的万能信号（含 ASR 错字变体：卧槽/卧草/我操）
- 类型词库：不同直播的爆点语言完全不同（吃瓜 vs 五杀 vs 反常识）
- 用户词库：主播黑话、圈内梗，系统不可能预知 → 用户自己加（一行一词，按强信号算）
- AI 自动发现词库 → 推迟 v0.4（先验证核心判断能力，见 D-008）

## D-008 为什么把词库自动发现 / 文本纠错 / 反馈分析推迟到 v0.4？

**原因**：v0.3 的核心目标是验证「AI 能不能像真正的直播剪辑师一样判断片段值不值得剪」。
核心没验证之前堆外围功能 = 在没打地基的地上盖楼。

**决策**：v0.3 只做核心流水线 + 攒数据（feedback.jsonl 只写不分析），v0.4 再回头做外围。

## D-009 API Key 为什么走环境变量 / api_key.txt，不写进代码？

安全常识 + 仓库是（虽然是私有）GitHub 仓库。env 优先，api_key.txt 兜底（网页版用），两者都已在 .gitignore 排除。

用户明确要求（2026-09-08）：初学者项目，Streamlit 纯 Python 可维护，不引入前端工程链。

## D-011 为什么 docs/ 交接文档体系在 v0.3 Phase 2 才建立？

## D-012 高光评分的五维标准（规范 v1.0，2026-09-09）

**决策**：高光判断的长期评分标准为五维加权：

| 维度 | 权重 | 含义 |
|---|---|---|
| 传播价值 | 30% | 陌生用户刷到，会不会停下来 |
| 情绪冲击 | 25% | 愤怒/惊讶/兴奋/搞笑/感动 |
| 冲突反转 | 20% | 观点冲突/意外结果/争议 |
| 独立观看价值 | 15% | 脱离直播上下文是否成立 |
| 内容价值 | 10% | 知识、信息价值 |

各直播类型在此基础上调整侧重（游戏：操作/胜负/反转；娱乐：情绪/冲突/梗；知识：信息密度/认知冲击）。
**落位**：写入海选/复审提示词的时机 = 下一次触碰 prompt_builder 时（P0 真实测试调优阶段），不在文档变更时提前改代码。

## D-013 云端部署架构：本地 ASR + 云端 AI 分析（规范 v1.0，2026-09-09）

**原因**：商业化后不能让用户上传视频——带宽与存储成本高。
**决策**：视频读取、ASR 全部在用户本地完成；云端只处理 AI 分析（文字稿上行，结果下行）。
同时降低用户电脑配置要求（P3）。v0.5 落地。

## D-014 文本纠错优先级由 v0.4 提前到 P1（规范 v1.0，2026-09-09）

**背景**：D-008 曾把文本纠错整体推迟到 v0.4（先验证核心判断能力）。
**修订**：规范 v1.0 将文本纠错第一阶段（用户词库管理 UI：添加/删除/修改/导入/导出）提为 P1，理由：**输入质量决定 AI 判断上限**——Whisper 的人名/游戏名/品牌错字会直接污染海选证据。
**注意**：这不是推翻 D-008——P0 仍是真实 AI 测试（核心验证依然最优先），只是纠错紧随其后；AI 辅助发现词库（第二阶段）仍推迟。
**落位**：新建 analysis/correction.py，禁止大规模重构现有模块。

## D-015 Token 展示规范修订：模式选择不露数字，运行前必须给预估（规范 v1.0，2026-09-09）

**背景**：D-005 规定 UI 不展示 token 数字。
**修订**：两者不冲突，规范更精确——
- 模式选择界面：只显示 快速/标准/精细 三个名字，不露参数（D-005 不变）
- **运行前**：必须显示预计消耗（如「预计 Token：约 18000，预计费用：¥0.08」）——budget.py 已具备估算能力，Phase 3 UI 接入
- 最大 token 限制用户可修改，默认 50000（config）

**决策**：WorkBuddy / Cursor / Claude Code / ChatGPT 等只能作为开发辅助工具，代码与文档不得依赖任何特定 AI 平台的私有机制。
交接靠 docs/（AI_HANDOVER / ARCHITECTURE / DECISIONS 先读，禁止直接重新理解项目）；每版本发布必须更新 VERSION_PLAN / DEVELOPMENT_LOG / AI_HANDOVER / CHANGELOG 四件套。

## D-017 召回优先：海选「宁多勿少」取代「宁缺毋滥」（v0.3.1，2026-09-09）

**背景**：P0 真实 API 首测（51 分钟稿）最终 0 推荐、1 个被拒候选。人工复盘发现该直播实际存在多个明显适合切片的爆点——问题不是覆盖不足，而是**候选生成阶段漏掉大量潜在高光 + 复审过滤过严**。海选提示词里的「宁缺毋滥」让 AI 倾向于「不够完美就不要」。

**决策**：策略从「严格筛选」调整为「**先保证召回率，再保证精准率**」：
- 海选：每区块至少 1 个候选（最多 3 个），拿不准就给，让复审去淘汰——第一轮不判生死
- 51 分钟直播目标候选池 15~30 个
- 「宁可多给候选，不要提前杀死可能爆的视频片段」写进海选 system 身份

**与 D-004 的关系**：不是推翻——复审仍有淘汰权（D-004 不变），只是淘汰权只保留给复审层，海选层不再提前用。

## D-018 复审从二元 recommend 改为 A/B/C 分级 + 零输出禁令（v0.3.1，2026-09-09）

**背景**：二元 recommend（推荐/拒绝）容易让 AI 一刀切输出 0 个。直播不是纪录片，很多爆款来自人物反应而非完整故事，硬套「完美才推荐」会误杀。

**决策**：
- 复审输出等级：**A 级**（≥8 强烈推荐）/ **B 级**（6~7 建议测试剪辑）/ **C 级**（5 备用素材）/ D（<5 淘汰 + reject_reason）
- **零输出禁令**：不允许把所有候选都打 4 分以下，除非同时满足：全部传播价值极低 + 无明显情绪节点 + 无独立成片可能
- 代码兜底（`_enforce_no_zero`）：复审全灭时，只要最佳候选 ≥4 分，强制保留 1 个为 C 级（标 `forced_keep`），请用户人工复核
- 数量模式重定义：自动精选 = 只出 A 级；候选池 = A+B+C 全展示；自定义数量 = 前 N 个分层标注（高质量/普通/备用）

## D-019 新增漏检质检层（质检 AI）（v0.3.1，2026-09-09）

**决策**：海选后、复审前插入一个独立角色「质检 AI」：
- 输入 = 各区块本地摘要（热/普、信号分、已有候选数、含强信号词的关键句，零 API 成本生成）+ 候选池简表
- 任务不是找高光，而是回答「有没有区块明显存在爆点却没进候选池」
- 查出可疑区块 → 用更宽的标准重扫该区块（second_pass 提示词），新候选去重后并入候选池
- 保险丝：最多重扫 `MISS_CHECK_MAX_CHUNKS=3` 个区块（防成本失控）；质检坏回复不崩（当无漏检处理）

## D-020 评分权重 v2：加入主播特色与争议讨论（v0.3.1，2026-09-09，修订 D-012）

**背景**：D-012 五维标准（传播 30/情绪 25/冲突反转 20/独立观看 15/内容 10）偏向「专业短视频运营」视角。实测教训：直播的高光逻辑不同——**很多爆款来自人物反应，而不是完整故事**。

**决策**（v2 权重，已写入海选提示词）：
- 传播潜力 30% / 情绪冲击 25% / **主播个人特色 15%** / **争议讨论 15%** / 独立成片 10% / 内容价值 5%
- 同时引入三类高光类型，各有专属评分维度：**事件型**（故事完整/冲突/信息价值）、**情绪型**（情绪强度/代入感/评论概率/表现力）、**梗型**（记忆点/模仿传播/标题空间/开头吸引力）

## D-021 Token 策略：不压缩换准确率，精细模式预算 5 万 → 8 万（v0.3.1，2026-09-09）

**背景**：51 分钟稿实测成本仅 ¥0.09（4.4 万输入 token）。用户明确：**用户真正付费的是准确率，不是节省几分钱**。

**决策**：不再为省钱压缩 token。精细模式预算由 50000 提到 80000（51 分钟稿不降级、每区块 3 候选）；快速/标准模式预算不变（本来就是低成本选项）。预算估算已计入质检与重扫的开销。

## D-022 评分模型 v3：运营视角五维 + 本地加权定级（v0.3.2，2026-09-09，修订 D-012/D-020）

**背景**：v0.3.1 真实复测出 7 个 A 级，人工复盘发现 AI 仍在当「直播总结助手」——饮料粉洒出来、发现军粮份量少这类「事故型」片段被打高分，部分 B 级反而更有短视频潜质（有误会/反差/记忆点）。v2 权重里没有「三秒吸引力」「反差」这类**传播结构**维度，全是内容维度，AI 只能靠「事大不大、情绪强不强」打分。

**决策**（评分模型 v3，替换 v2 六维）：
- 五维权重：**三秒吸引力 30 / 反差意外 25 / 人物表现力 20 / 独立成片 15 / 事件完整度 10**（config.SCORE_V3_WEIGHTS）
- 判断总纲写进提示词：**「一个不了解主播的新用户刷到这个片段，为什么会停下来？」**
- **复审 AI 只输出五个子分（1-10），不再输出 final_score/grade**；总分由本地按权重加权算出、等级由本地按分数线定——定级可解释、可审计，杜绝 AI「先给个漂亮理由、再顺手打个 9 分」
- 典型案例 few-shot 校准判断（写进复审提示词）：黄腐鸡误当咖啡（误会+反差）＝高价值；军粮「像纸盒子」/罐头「像指甲盖」（具体比喻＝天然标题与记忆点）＝高价值；饮料粉洒出来（纯事故）/"哇好少"（单纯惊讶）＝低价值

**与 D-012/D-020 关系**：修订而非推翻——传播价值导向没变，变的是「用什么维度衡量传播」：内容维度（情绪/争议）降权或删除，换成能直接解释「陌生人为什么停留」的维度。

## D-023 「不值得剪」负面清单：命中即本地封顶 B 级（v0.3.2，2026-09-09）

**背景**：负面规则写进提示词只是「建议」，AI 会选择性无视——「饮料粉洒出来」这类事故仍被捧上 A 级。

**决策**：负面规则升级为**代码层硬约束**：
- 复审时 AI 对每个候选勾选命中的规则（negative_flags，只能从清单选）：**普通失误 / 普通展示 / 单纯惊讶 / 依赖上下文 / 普通评价**
- 本地 `_apply_negative_cap`：命中任一即把该候选封顶为 B 级（config.NEGATIVE_RULE_CAP_GRADE），进不了 S/A；**只降不升**，本来就是 C/D 的候选不受影响
- 清单放 config（NEGATIVE_RULES），要增删规则只改配置不改代码

## D-024 分级体系升为 S/A/B/C/D 五级 + 双理由必答（v0.3.2，2026-09-09，修订 D-018）

**背景**：A 级（≥8）跨度太大——8 分和 9.9 分不是一个量级，爆款苗子被埋在一堆「还不错」里。

**决策**：
- 分级线：**S ≥ 9.0 爆款候选 / A ≥ 8.0 强推荐 / B ≥ 6.0 测试素材 / C ≥ 5.0 备用素材 / D 淘汰**（S 级不设数量上限，宁缺勿滥交给分数线本身）
- 数量模式重定义：自动精选 = 只出 S/A（AI 盖章值得剪）；候选池 = S/A/B/C 全展示；自定义数量 = 按终审分数取前 N 并标注质量名
- 复审每个候选**必答两个问题**：`why_cut`（为什么值得剪 = 陌生人为何停留 + 核心传播点，写不出来说明可能不值得剪）与 `risk`（最大风险/短板，**禁止写「无」**）——逼 AI 对推荐负责，也给用户审计抓手
- D 级淘汰理由由本地组装（risk 或命中规则），不让 AI 写套话
